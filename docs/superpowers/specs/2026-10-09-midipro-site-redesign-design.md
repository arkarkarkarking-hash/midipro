- 상태: 승인됨 (grill-me 점검 반영, 2026-10-09)
- 근거 문서: 미디프로 성장 로드맵 (Claude Docs)

## 1. 목표와 범위

### 목표

신규 상담 유입을 늘린다. 로드맵 KPI 기준으로 월 상담 8건 이상, 월 신규 등록 3~4명이다. 홈페이지는 검색으로 들어온 학부모와 학생에게 **입시 결과와 실제 입시곡**을 보여주고, **전화 상담**으로 연결하는 역할을 맡는다.

### 정체성과 타깃

- 포지셔닝: 천안 불당동의 미디 입시 전문 학원. 사이트는 미디 입시 중심으로만 소개하고, 피아노·화성학·음향은 미디 입시를 돕는 연계 수업으로 언급한다.
- 1순위 타깃은 고1~2 학생과 학부모. 그다음은 중2~3·취미생, 고3·N수생, 성인 취미생이다.
- 메인 타이틀: **"곡으로 합격을 만드는 학원."**
- "충청권 미디 입시 1등" 같은 최상급 표현은 사이트에 쓰지 않는다. 객관적 근거 없는 최상급 표현은 표시광고법상 부당광고가 될 수 있다.
- 입시곡에는 불합격한 학생의 곡도 있다. 사이트 전체에서 "합격곡"이 아니라 **"입시곡"**이라고 쓰고, 입시 결과와 입시곡을 서로 연결하지 않는다. 일부 곡에만 합격 표시가 붙으면 나머지 학생의 결과가 드러나기 때문이다.
- 입시 결과는 숫자로 요약하지 않고 담담하게 보여준다.

### 1차 범위 (이번 설계)

1. 공개 사이트 8개 페이지와 곡별 페이지
2. 페이지를 이동해도 끊기지 않는 음원 플레이어
3. SEO, 네이버·구글 서치어드바이저 대응, 파비콘, OG 이미지
4. 동작하는 로그인 (관리자, 강사, 수강생)
5. 수강생 마이페이지: 내 곡, 시험 결과
6. 관리자 화면: 계정 관리, 수강생 계정에 곡 연결, 시험 결과 입력

### 출시 단계

| 단계 | 시점 | 내용 |
|---|---|---|
| A | 2주 차 | 공개 사이트 전체, SEO, 플레이어 |
| B | 3주 차 | 로그인, 수강생 마이페이지(내 곡), 관리자 화면(계정, 곡 연결) |
| C | 시험 양식 파일을 받고 1주 안 | 시험 결과 입력(관리자)과 조회(마이페이지) |

자료가 아직 없는 페이지(강사진 등)는 자료가 들어올 때까지 메뉴와 sitemap에서 숨긴다. 빈 "준비 중" 페이지는 공개하지 않는다.

### 1차에서 하지 않는 것

- 온라인 상담 신청 폼, 상담 기록 저장, 이메일 알림. 상담은 전화로만 받는다. 정보 유출 위험을 줄이고, 경쟁사가 학원 정보를 쉽게 가져가지 못하게 하기 위해서다.
- 카카오톡 채널
- 수강료 게시. "상담 시 안내"로 표시한다.
- 비밀번호 변경, 비밀번호 찾기
- 강사 화면, 관리자와 강사가 공유하는 주간 코멘트, 웹으로 시험 보기. 2차 설계에서 다룬다.
- 관리자 화면에서 음원이나 실적을 직접 업로드하는 기능. 2차로 미룬다.
- 보컬, 드럼, 기타, 베이스 과정 소개

## 2. 전체 구조

```
midipro.kr (Cloudflare Worker 하나로 운영)
├─ 공개 페이지: Astro가 빌드 시점에 만든 정적 HTML
├─ /api/*: 로그인, 로그아웃, 계정 관리 API (Worker)
├─ /login, /admin, /my: 로그인이 필요한 화면 (검색 노출 차단)
├─ D1: 계정, 세션, 수강생-곡 연결, 시험 결과
└─ R2: 음원 파일 (media.midipro.kr로 제공)
```

- 프레임워크: Astro. 페이지 이동은 Astro ClientRouter를 쓰고, 플레이어는 `transition:persist`로 유지한다.
- 호스팅: Cloudflare Workers의 정적 자산 기능과 Worker 코드. 저장소의 기존 `wrangler.jsonc` 방식을 이어간다.
- 공개 콘텐츠는 저장소 안의 데이터 파일로 관리한다: `src/data/tracks.json`, `results.json`, `teachers.json`, `courses.json`, `site.json`. 계정, 곡 연결, 시험 결과는 D1에 저장한다.
- 배포: GitHub의 `main` 브랜치에 푸시하면 Cloudflare가 자동으로 빌드하고 배포한다.
- 비용: Cloudflare 무료 플랜 안에서 운영한다. 도메인 비용만 별도다.
- 개발 환경: 이 Mac(Intel)에 Node.js LTS를 설치해야 한다.

### 컨셉: 녹음실 랙 하드웨어 + 무광 메탈

레코딩 스튜디오의 19인치 랙 장비처럼 만든다. 레이아웃의 정보 구조는 Apple 팟캐스트를 참고한다. 큰 추천 영역, 섹션 제목과 목록, 떠 있는 미니 플레이어, PC에서는 왼쪽 사이드바로 구성한다.

- **랙 모듈**: 모든 섹션은 랙 모듈이다. 좌우 16px 랙 귀에 6px 나사(와셔 링, 모듈마다 다른 나사 머리 각도)와 장착 슬롯을 둔다. 모듈 사이는 3px 간격과 그림자로 나누고, 배경은 랙 레일 줄무늬다.
- **질감**: 모듈 면은 헤어라인 브러시드 무광 알루미늄, 본문 영역은 무광 차콜(`#111112`~`#1E1E21`)에 미세한 노이즈를 깐다.
- **장비 요소**: 파형은 오목한 디스플레이 창 안에 넣고, 재생 버튼은 트랜스포트 키캡, 곡 번호는 채널 번호(CH01), 정보 라벨은 각인 글자(ADDR · HOURS · TEL), 노브 손잡이 같은 널링 띠를 쓴다. 미니 플레이어와 하단 버튼도 각각 1U 모듈이다.
- **강조색**: 블루(`#5B7CFA`)에서 바이올렛(`#8F63F0`)으로 가는 그라데이션. LED 한 줄, 전원 LED, 재생 진행 바, 재생 중 채널 표시, 파형의 재생 구간에만 쓴다. 발광 효과는 쓰지 않는다.

## 5. 음원

### 데이터 (`src/data/tracks.json`)

```json
{
  "slug": "2025-hwang-siyun",
  "title": "25 황시윤 입시곡",
  "artists": ["황시윤"],
  "category": "admissions",
  "year": 2025,
  "label": "입시곡",
  "file": "admissions/2025-hwang-siyun.mp3",
  "duration": 168,
  "featured": true,
  "links": {}
}
```

- `category`는 `admissions`(입시곡), `songcamp`(송캠프), `release`(발매곡) 중 하나다. 발매곡은 `links`에 외부 스트리밍 링크를 넣는다.
- 학생 이름은 실명으로 공개한다(사용자 결정). 이름 표기는 데이터 파일에만 있으므로, 나중에 가려야 할 때 이 파일만 고치면 된다.
- `duration`과 파형 데이터는 빌드 스크립트가 음원에서 자동으로 추출한다.

### 저장과 재생

- 기존 `audio/` 폴더의 78곡을 영문 이름으로 바꿔 R2 버킷 `midipro-audio`에 올린다. 원본 `audio/` 폴더는 저장소에 백업으로 남기고, 사이트 배포 대상에서만 제외한다(`.assetsignore`).
- 재생 주소는 `media.midipro.kr`로 한다. 도메인을 옮기기 전까지는 R2 임시 공개 주소를 쓴다. 구간 이동(Range 요청)은 R2가 기본으로 지원한다.
- 곡 추가 절차: R2에 파일을 올리고, `tracks.json`에 항목 하나를 추가하고, 푸시한다.

### 플레이어

- 페이지를 이동해도 재생이 끊기지 않는다.
- 재생 목록은 사용자가 재생을 시작한 목록이 된다. 이전 곡, 다음 곡, 구간 이동, 볼륨(PC)을 지원한다.
- Media Session API로 휴대폰 잠금화면과 이어폰 버튼 조작을 지원한다.
- 다운로드 버튼은 두지 않는다.
- 재생에 실패하면 미니 플레이어에 "재생할 수 없습니다"를 표시하고 다음 곡으로 넘어가지 않는다.

## 6. 로그인과 관리자

### 계정

- 역할: `admin`, `teacher`, `student`. 회원가입은 없고, 관리자가 아이디와 비밀번호를 정해 전달한다.
- 저장 정보: 아이디, 이름, 출생연도, 역할. 연락처 등 다른 개인정보는 받지 않는다. 나이는 출생연도로 계산해 관리자 화면에만 보여준다. 마이페이지에는 이름을 표시한다.
- 14세 미만 학생의 보호자 동의는 학원 등록 서류로 받는다(학원에서 준비 완료).
- 비밀번호 변경 기능은 없다. 바꿔야 하면 관리자가 새로 지정한다.
- 관리자는 모든 화면에 접근한다. 강사 계정은 1차에서 로그인 후 "준비 중" 화면만 본다.
- 첫 관리자 계정은 배포할 때 명령줄 스크립트로 만든다.

### D1 테이블

```
users(id, login_id UNIQUE, name, birth_year, role, password_hash, status, failed_count, locked_until, created_at, last_login_at)
sessions(id, user_id, expires_at, created_at)
user_tracks(user_id, track_slug, PRIMARY KEY(user_id, track_slug))
exam_results(...)  -- 단계 C에서 시험 양식 파일을 받은 뒤 정의한다
```

### 보안

- 비밀번호는 PBKDF2-SHA256(Workers Web Crypto, 반복 100,000회)과 사용자별 솔트로 저장한다.
- 세션은 무작위 토큰을 `HttpOnly; Secure; SameSite=Lax` 쿠키에 담는다. 유효기간은 7일이고, 로그아웃하면 D1에서 삭제한다.
- 같은 계정으로 5회 연속 실패하면 15분 동안 잠근다. 로그인 화면에는 Cloudflare Turnstile을 붙인다.
- `/login`, `/admin`, `/my`에는 `noindex`를 달고 `robots.txt`에서도 막는다.
- 상태를 바꾸는 API는 POST만 받고, 요청 출처(Origin)를 확인한다.

### 화면

- `/login`: 아이디, 비밀번호, Turnstile
- `/admin` (관리자만)
  - 계정: 목록, 생성(아이디, 이름, 출생연도, 역할, 비밀번호), 비밀번호 재지정, 비활성화와 활성화
  - 곡 연결: 수강생 계정에 `tracks.json`의 곡을 하나 이상 연결한다. 송캠프 곡처럼 한 곡에 여러 학생을 연결할 수 있다.
  - 시험 결과 입력 (단계 C)
- `/my`
  - 수강생: "OOO님", 내 곡 목록과 재생, 시험 결과(단계 C). 아직 내용이 없는 항목은 화면에 넣지 않는다.
  - 강사: "준비 중" 안내와 로그아웃

## 7. SEO와 마케팅

### 페이지 공통

- 페이지마다 고유한 `title`과 `description`, canonical 주소, `lang="ko"`
- 대표 주소는 `https://midipro.kr`이다. `www`와 `http`로 들어오면 301로 넘긴다.
- 페이지당 `h1`은 하나만 두고, 이미지에는 대체 텍스트를 넣고, 위치 경로(breadcrumb)를 표시한다.

### 검색엔진용 파일

- `sitemap.xml`: 자동 생성한다. 곡 상세 페이지를 포함한다.
- `robots.txt`: Yeti(네이버)와 Googlebot을 허용하고, `/admin`, `/my`, `/login`, `/api`를 막는다.
- `rss.xml`: 최근 추가된 곡을 담는다. 네이버 서치어드바이저에 제출한다.

### 구조화 데이터 (JSON-LD)

- 모든 페이지: `MusicSchool`이자 `LocalBusiness`. 이름, 주소, 전화, 운영시간, 좌표, `sameAs`(블로그, 인스타그램, 유튜브)를 넣는다.
- 곡 상세: `MusicRecording`
- 하위 페이지: `BreadcrumbList`

### 네이버 대응

- 자바스크립트 없이도 모든 내용이 HTML에 들어 있다.
- 학원 이름, 주소, 전화 표기를 네이버 플레이스와 똑같이 맞춘다.
- 지도는 삽입하지 않고 "네이버 지도로 보기", "카카오맵으로 보기" 버튼을 둔다.

### 마케팅 요소

- 파비콘: `favicon.ico`, `favicon.svg`, `apple-touch-icon.png`(180px), `icon-192.png`, `icon-512.png`, `site.webmanifest`. `theme-color`는 `#111112`다. 로고는 작은 크기에서 읽히는지 확인하고, 읽히지 않으면 로고에서 단순화한 마크를 쓴다.
- OG 이미지(1200×630)
  - 기본 이미지: 랙 모듈 배경, LED 선, 로고, 메인 타이틀
  - 곡 상세: 곡 제목과 연도를 넣어 빌드할 때 자동으로 만든다.
  - 카카오톡과 네이버 미리보기를 위해 `og:title`, `og:description`, `og:image`, `og:url`을 모든 페이지에 넣는다.
- 분석: Cloudflare Web Analytics. 쿠키를 쓰지 않는다. 유입 경로와 전화 버튼 클릭(페이지별)을 집계한다.

### 성능 목표

모바일 Lighthouse에서 성능, SEO, 접근성, 권장사항 모두 90점 이상

## 8. 배포와 도메인 이전 (마지막 단계)

1. 미리보기: 개발 중에는 `*.workers.dev` 주소로 확인한다. 이 주소는 검색 노출을 막는다.
2. 도메인: 카페24에서 `midipro.kr`의 네임서버를 Cloudflare로 바꾼다. 도메인 등록은 카페24에 그대로 둔다. 카페24 메일은 쓰지 않으므로 MX 레코드(`mw-002.cafe24.com`)는 옮기지 않는다.
3. 연결: Worker에 `midipro.kr`, R2에 `media.midipro.kr`를 연결한다. `www`는 301로 넘긴다.
4. 카페24 호스팅은 새 사이트가 정상 동작하는 것을 확인한 뒤 해지한다.
5. 등록: 네이버 서치어드바이저와 구글 서치콘솔에서 소유를 확인하고 `sitemap.xml`과 `rss.xml`을 제출한다.

## 9. 테스트

## 10. 입시 결과 (`results.json`)
